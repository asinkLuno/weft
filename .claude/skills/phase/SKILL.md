# Weft Phase：时间表达与相对偏移

`Phase` 是 YAML 时间进入运行时的原始表示（`src-tauri/src/weft/phase.rs`）：一棵「锚点 + 分量」的小树。它不理解年月日的长短，不做进位借位——历法语义全部交给 Calendar。实体的 `base_time` 和事件的 `start_time` / `end_time` 共用同一套解析规则（`phase.rs:46-47`）。

## 三种输入形状

```yaml
42                              # 标量整数，等价于 [42]
[1991, 9, 1, 19]                # 绝对时间：分量数组
[[1991, 9, 1, 19], 0, 0, 0, 2]  # 偏移值：首项是数组 → 递归解析为锚点，其余整数为偏移分量
```

- 分量按历法**从大到小**排列：内置公历是 `[年, 月, 日, 时, 分, 秒]`，尾部可省略（展平补 0），所以 `[1991, 9, 1]` 就是 1991-9-1 00:00:00。
- 首项是数组时，该首项递归作为锚点（anchor），剩余整数是当前层的偏移分量——这就是相对偏移的机制。

## 偏移值详解

偏移是**从锚点出发的逐分量加法，从第一个分量（年槽）对齐**，不是从末尾对齐：

| 写法 | 展平结果（公历 N=6） | 含义 |
| --- | --- | --- |
| `[[2025, 4, 2, 10], 0, 0, 0, 2]` | `[2025, 4, 2, 12, 0, 0]` | 锚点 +2 小时（第 4 槽） |
| `[[1991, 9, 1], 0, 0, 0, 2]` | `[1991, 9, 1, 2, 0, 0]` | 纯日期锚点也能加小时——时槽本来就补 0 |
| `[anchor, 2]` | 年槽 +2 | 陷阱：想加小时必须补零 `[anchor, 0, 0, 0, 2]` |
| `[[2025, 4, 2], 0, -1]` | `[2025, 3, 2, 0, 0, 0]` | 负分量 = 分量减法 |

规则（`accumulate`，`phase.rs:91-113`）：

- 建一个长度为 N 的零向量，从**最内层锚点**逐层往外累加，每层分量都从第 0 槽对齐相加。
- 少写的尾部分量保持 0；任何一层分量数超过 N 报错。
- checked 运算，溢出报 `TimeOffsetOutOfRange`。
- **不进位不借位**：小时加到 25 就留在小时槽，借进借位由历法的 `normalize`（宿主实现为 `from_tick(to_tick(v))`）统一处理。

锚点可以嵌套——`[[[2025, 4, 2, 10], 0, 0, 0, 2], 1, 2, 3]` → `[2026, 6, 5, 12, 0, 0]`（先 +2 小时，再年 +1、月 +2、日 +3）。

### YAML 锚点复用

偏移值的典型用法是配合 YAML 锚点，把一个时间作为另一个时间的锚（见 `examples/story.yaml`）：

```yaml
event:
  分院帽晚宴:
    start_time: &feast [1991, 9, 1, 19]
    end_time: [*feast, 0, 0, 0, 2]   # 宴会开始两小时后结束
  蛇怪袭击:
    start_time: &basilisk [1993, 4, 20, 8]
    end_time: [*basilisk, 0, 0, 0, 6]
```

### base_time 也可以是偏移值

实体 `base_time` 走同一条解析路径，锚点偏移形态合法，构建时同样经历展平→历法归一化→生成展示文案：

```yaml
entity:
  哈利·波特:
    base_time: [1980, 7, 31]              # 常规：绝对时间
  神秘的钟摆:                              # 合法但少见：锚定偏移
    base_time: [[1980, 7, 31, 0], 0, 0, 1, 12]   # = 1980-8-1 12:00（日 +1、时 +12）
```

习惯上 `base_time` 写绝对时间（人物出生日期等）；偏移形态主要用在事件的 `start_time` / `end_time` 上表达持续时间。

## 分量数 N 由历法决定

- 内置公历：`src-tauri/rune/gregorian.rn` 的 `pub fn components()` 返回 6（年月日时分秒）。
- 自定义历法：历法脚本 `pub fn components()` 返回分量数（1–64，见 `docs/src/rune-calendar.md`，示例 `examples/lunar.rn`）。分量含义随历法变化，偏移值加在哪个槽位也随之变化。

## 解析报错对照

| 错误 | 原因 |
| --- | --- |
| `TimeNonemptyList` | 值不是非空数组——包括把字符串当时间（`base_time: "1991年"`）和空列表 `[]` |
| `TimeIntegerComponent` | 分量不是整数（浮点、字符串数字都不行） |
| `TooManyTimeComponents` | 某一层的分量数超过历法 N |
| `TimeOffsetOutOfRange` | 展平/相减时 checked 运算溢出 |

## 责任边界

Phase 只负责结构、整数校验和溢出安全；Calendar 负责日历语义——进位借位（`normalize`）、时间先后（`to_tick`）、展示文案（`humanize`）。同一套时间表达结构因此既能跑公历也能跑自定义历法。实体基准时间之间的差值展示用 `Phase::subtract`（两边各自展平后逐分量 checked 相减，同样不归一化）。
